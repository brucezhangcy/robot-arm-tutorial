Chapter 4

Position Control — Joint Space

The simplest way to move a robot arm is to say "I want joint 1 at 45°, joint 2 at −30°…" and let the software figure out a safe path to get there. This chapter shows you how to do exactly that using Python and MoveIt 2. By the end, you will have working code that moves the Panda to any position you choose — entirely in simulation, so nothing can go wrong with real hardware.

Key Terms — Chapter 4

Joint space
Describing the arm's configuration by listing the angle of each joint (7 numbers for the Panda).
Cartesian space
Describing the arm's configuration by the position and orientation of the gripper in 3D space (x, y, z + rotation).
C-space
Configuration space — the 7D mathematical space where every possible arm configuration is one point.
Trajectory
A planned sequence of positions with timing — waypoints plus the exact times at which the arm must reach each one.
Waypoint
One target position in a trajectory; the arm passes through a series of waypoints in order.
PID controller
Proportional-Integral-Derivative — a standard algorithm that corrects the difference between where the arm is and where it should be, 1,000 times per second.
Planning pipeline
The sequence of steps MoveIt 2 runs to produce a ready-to-execute trajectory: plan → smooth → add timing → send to controller.
Action server
A ROS 2 pattern for long-running tasks; the server streams progress updates while working, then returns a final result.
RRTConnect
A bidirectional sampling-based planner that grows two trees from start and goal until they connect.
TOTG
Time-Optimal Trajectory Generation; assigns timestamps to raw planner waypoints to maximise speed within joint limits.
JointTrajectoryController
ros2_control controller that tracks a time-parameterized joint trajectory using PID.
Velocity scaling
A multiplier (0–1) applied to joint velocity limits to slow planned motions.

4.1 Joint Space vs. Cartesian Space

There are two natural coordinate systems for describing a robot arm's configuration:

SpaceVariablesDimensionBest for
Joint spaceJoint angles \(\mathbf{q} = [q_1,\ldots,q_7]\)\(\mathbb{R}^7\)Named poses, home positions
Cartesian (task) spaceEEF pose \((x,y,z,R)\)\(SE(3)\)Manipulation, straight-line paths

Joint-space control (this chapter) is simpler to reason about: you specify where each motor should end up, and the planner finds a collision-free path through joint angles. The end-effector path in Cartesian space is not straight — it follows whatever arc the joints trace out naturally. For moving to a named home position or a standard pick pose, that is perfectly fine. But when the shape of the path matters — drawing a straight line or approaching an object along a vertical axis — use Cartesian control instead (Chapter 5).

4.2 The MoveIt 2 Planning Pipeline

When you call move_group.go(), MoveIt 2 runs a planning pipeline — a sequence of stages that transforms your high-level goal into a stream of joint position setpoints delivered to the JointTrajectoryController at 1 kHz. This is the same pipeline described at a high level in Chapter 1's software stack; here you see the individual stages. Figure 4.1 shows every stage.

Analogy — motion planning as GPS navigation: When Google Maps plans a route, it doesn't move in a straight line across a map — it navigates a graph of real roads, avoids closed roads and traffic jams, and respects one-way streets. MoveIt 2 does the same thing in "joint-angle space": the 7 joint angles define a 7-dimensional space, and the planner finds a path through that space that avoids all collisions and respects joint limits. The PID controller at the end is like cruise control: once the route is planned, it automatically adjusts the throttle every millisecond to stay exactly on track.

4.2.1 The Configuration Space (C-space)

The planner does not work in 3D Euclidean space. It works in C-space (configuration space) — the 7-dimensional space of all possible joint angle vectors. This concept appeared briefly in Chapter 2 when we discussed the workspace: the workspace is the image of C-space under forward kinematics. Each point in C-space is one complete arm configuration; each collision-free point is in free space \(C_{\text{free}}\). The planner's job is to find a path from the start point to the goal point entirely within \(C_{\text{free}}\). RRTConnect (the default planner) grows two random trees from start and goal simultaneously until they meet [1].

4.2.2 Time Parameterization

The raw planner output is a sequence of waypoints with no timing information. MoveIt 2 then runs a time parameterizer (TOTG — Time-Optimal Trajectory Generation) that assigns timestamps to each waypoint such that joint velocity limits (e.g., 2.175 rad/s for joint 1) and acceleration limits are never exceeded [2]. You can scale the resulting speed down via move_group.set_max_velocity_scaling_factor(0.1) for extra caution.

4.4 Code Examples

Before running any code in this section, make sure the simulation is already running. Open a terminal (or Docker exec shell), source your workspace, and start the simulation with the launch command from Chapter 3 §3.5. Then open a second terminal for your Python script.

4.4.1 Move to a Joint Goal

joint_goal_client.py — run in a second terminal while launch_sim.sh is running
#!/usr/bin/env python3
"""
Move the Panda to a named joint configuration via MoveIt 2.
Requires: simulation (ch03 launch_sim.sh) to be running.
"""

import rclpy
from rclpy.node import Node
from moveit.planning import MoveItPy
from moveit.core.robot_state import RobotState
import numpy as np


class JointGoalClient(Node):
    def __init__(self):
        super().__init__('joint_goal_client')
        self.moveit = MoveItPy(node_name='joint_goal_moveit')
        self.arm = self.moveit.get_planning_component('panda_arm')
        self.get_logger().info('MoveIt 2 initialized.')

    def move_to_joint_config(self, q: list[float], vel_scale: float = 0.3) -> bool:
        """
        Plan and execute a move to joint configuration q.

        Args:
            q:         7-element list of joint angles [rad]
            vel_scale: max velocity as fraction of joint limit (0.0–1.0)

        Returns:
            True on success, False on planning or execution failure.
        """
        robot_model = self.moveit.get_robot_model()
        robot_state = RobotState(robot_model)
        joint_names = [f'panda_joint{i}' for i in range(1, 8)]
        robot_state.set_joint_group_positions('panda_arm', q)

        self.arm.set_start_state_to_current_state()
        self.arm.set_goal_state(robot_state=robot_state)

        plan_result = self.arm.plan(
            single_plan_parameters={'max_velocity_scaling_factor': vel_scale,
                                    'max_acceleration_scaling_factor': vel_scale}
        )
        if not plan_result:
            self.get_logger().error('Planning failed.')
            return False

        execute_result = self.moveit.execute(plan_result.trajectory, controllers=[])
        if not execute_result:
            self.get_logger().error('Execution failed.')
            return False

        self.get_logger().info('Motion complete.')
        return True

    def move_to_ready(self) -> bool:
        """Move to the Panda 'ready' pose (all joints at comfortable positions)."""
        q_ready = [0.0, -np.pi/4, 0.0, -3*np.pi/4, 0.0, np.pi/2, np.pi/4]
        self.get_logger().info('Moving to ready pose...')
        return self.move_to_joint_config(q_ready, vel_scale=0.2)


def main():
    rclpy.init()
    client = JointGoalClient()
    success = client.move_to_ready()
    print('Success:', success)
    rclpy.shutdown()


if __name__ == '__main__':
    main()

4.4.2 Direct Trajectory Client (bypasses MoveIt 2)

This approach skips MoveIt 2's planner and sends trajectory commands directly to the controller. There is no collision checking — only use this for simple, pre-verified motions. Run in a terminal while the simulation is running (the same setup as §4.4.1).

joint_trajectory_client.py — run in a second terminal while launch_sim.sh is running
#!/usr/bin/env python3
"""
Send a JointTrajectory message directly to the JointTrajectoryController
action server, bypassing MoveIt 2's planner. Use only for simple,
pre-verified motions — no collision checking is performed.
"""

import rclpy
from rclpy.node import Node
from rclpy.action import ActionClient
from control_msgs.action import FollowJointTrajectory
from trajectory_msgs.msg import JointTrajectoryPoint
from builtin_interfaces.msg import Duration
import numpy as np


class DirectTrajectoryClient(Node):
    def __init__(self):
        super().__init__('direct_trajectory_client')
        self._client = ActionClient(
            self,
            FollowJointTrajectory,
            '/panda_arm_controller/follow_joint_trajectory'
        )

    def send_trajectory(self, waypoints: list[list[float]],
                        time_from_start_s: list[float]) -> bool:
        """
        Send a joint trajectory with explicit waypoints and timestamps.

        Args:
            waypoints: list of 7-element joint angle vectors
            time_from_start_s: timestamp (seconds) for each waypoint

        Returns:
            True on success.
        """
        joint_names = [f'panda_joint{i}' for i in range(1, 8)]

        goal = FollowJointTrajectory.Goal()
        goal.trajectory.joint_names = joint_names

        for q, t in zip(waypoints, time_from_start_s):
            pt = JointTrajectoryPoint()
            pt.positions = [float(x) for x in q]
            secs = int(t)
            pt.time_from_start = Duration(sec=secs,
                                          nanosec=int((t - secs) * 1e9))
            goal.trajectory.points.append(pt)

        self.get_logger().info(
            f'Sending trajectory with {len(waypoints)} waypoints...'
        )
        if not self._client.wait_for_server(timeout_sec=5.0):
            self.get_logger().error('Action server not available!')
            return False

        future = self._client.send_goal_async(goal)
        rclpy.spin_until_future_complete(self, future)
        goal_handle = future.result()

        if not goal_handle.accepted:
            self.get_logger().error('Goal rejected.')
            return False

        result_future = goal_handle.get_result_async()
        rclpy.spin_until_future_complete(self, result_future)
        result = result_future.result().result

        self.get_logger().info(
            f'Trajectory done. Error code: {result.error_code}'
        )
        return result.error_code == FollowJointTrajectory.Result.SUCCESSFUL


def main():
    rclpy.init()
    client = DirectTrajectoryClient()

    # Three-waypoint sweep of joint 1
    q0 = [0.0] * 7
    q1 = [0.5, -np.pi/4, 0, -3*np.pi/4, 0, np.pi/2, np.pi/4]
    q2 = [1.0, -np.pi/4, 0, -3*np.pi/4, 0, np.pi/2, np.pi/4]

    client.send_trajectory(
        waypoints=[q0, q1, q2],
        time_from_start_s=[0.0, 2.5, 5.0]
    )
    rclpy.shutdown()


if __name__ == '__main__':
    main()

4.4.3 Monitor Joint States

monitor_joint_states.py
#!/usr/bin/env python3
"""
Subscribe to /joint_states and print position, velocity, and effort
for all 7 Panda joints in a formatted table at 10 Hz.
Press Ctrl+C to stop.
"""

import rclpy
from rclpy.node import Node
from sensor_msgs.msg import JointState
import numpy as np


class JointStateMonitor(Node):
    def __init__(self):
        super().__init__('joint_state_monitor')
        self._sub = self.create_subscription(
            JointState, '/joint_states', self._callback, 10
        )
        self._timer = self.create_timer(0.1, self._print_table)
        self._latest: JointState | None = None

    def _callback(self, msg: JointState):
        self._latest = msg

    def _print_table(self):
        if self._latest is None:
            return

        msg = self._latest
        # Filter to panda_joint1..7 only (ignore finger joints)
        panda_idx = [i for i, n in enumerate(msg.name)
                     if n.startswith('panda_joint') and 'finger' not in n]

        print('\033[2J\033[H', end='')  # clear terminal
        header = f"{'Joint':<16} {'Pos (rad)':>12} {'Vel (rad/s)':>12} {'Effort (Nm)':>12}"
        print(header)
        print('-' * 56)
        for i in panda_idx:
            name = msg.name[i]
            pos  = msg.position[i] if msg.position else 0.0
            vel  = msg.velocity[i] if msg.velocity else 0.0
            eff  = msg.effort[i]   if msg.effort   else 0.0
            print(f'{name:<16} {pos:>12.4f} {vel:>12.4f} {eff:>12.3f}')


def main():
    rclpy.init()
    rclpy.spin(JointStateMonitor())
    rclpy.shutdown()


if __name__ == '__main__':
    main()
Chapter 4 Summary
  • Joint-space motion planning is the simplest form of arm control: you specify target joint angles and MoveIt 2 finds a smooth, collision-free path through the 7-dimensional space of all possible configurations — without you needing to think about how the gripper traces through 3D space.
  • The planning pipeline does three things automatically: samples a collision-free path (OMPL planner), simplifies the path to remove unnecessary detours, then assigns speed and acceleration limits so the hardware is never overloaded. You set the goal; MoveIt 2 figures out everything in between.
  • Your Python code is not what moves the arm. The JointTrajectoryController inside ros2_control is — it runs a PID loop at 1 kHz, one per joint, tracking the planned trajectory. Your code simply sends the goal and waits. Understanding this separation is key to diagnosing why the arm "didn't follow the plan."
  • For timing-critical applications where you need exact control over the speed and timing of each waypoint, you can bypass MoveIt 2 and send trajectories directly to the controller — useful for synchronized multi-arm tasks or precise pick-and-place timing.

Exercises

  1. Run joint_goal_client.py in simulation. While the arm is moving, open a second terminal and run monitor_joint_states.py. Observe which joints are changing fastest. Do they correlate with the joint that has the most influence according to your Jacobian results from Chapter 2?
  2. Modify joint_goal_client.py to move the arm to a configuration with q[0] = 1.5 (joint 1 rotated ~86°). Does the planner succeed? What happens if you try q[0] = 2.9 (near the joint limit of 2.9 rad)?
  3. Change vel_scale from 0.3 to 0.05. How does the trajectory duration change? How does it change the smoothness of motion in RViz?
