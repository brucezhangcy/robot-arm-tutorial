Appendix A · ROS 2 & Python Quick Reference

This appendix provides a compact reference for the ROS 2 concepts and Python patterns used throughout the tutorial. It is not a substitute for the official ROS 2 documentation but serves as a quick lookup during coding.

A.1 Essential ROS 2 CLI Commands

# ── Nodes ─────────────────────────────────────────────────────────
ros2 node list                        # list running nodes
ros2 node info /node_name             # show publishers, subscribers, services

# ── Topics ────────────────────────────────────────────────────────
ros2 topic list                       # list all active topics
ros2 topic echo /joint_states         # print messages as they arrive
ros2 topic hz /joint_states           # measure publish rate
ros2 topic info /joint_states         # message type + pub/sub count
ros2 topic pub --once /topic std_msgs/msg/String "data: hello"

# ── Services ──────────────────────────────────────────────────────
ros2 service list
ros2 service call /error_recovery franka_msgs/srv/ErrorRecovery

# ── Actions ───────────────────────────────────────────────────────
ros2 action list
ros2 action send_goal /move_action_server \
    control_msgs/action/FollowJointTrajectory {}

# ── Parameters ────────────────────────────────────────────────────
ros2 param list /node_name
ros2 param get /node_name param_name
ros2 param set /node_name param_name value

# ── Launch ────────────────────────────────────────────────────────
ros2 launch package_name file.launch.py arg:=value

# ── Controllers ───────────────────────────────────────────────────
ros2 control list_controllers
ros2 control switch_controllers --activate ctrl1 --deactivate ctrl2

# ── TF ────────────────────────────────────────────────────────────
ros2 run tf2_tools view_frames           # render TF tree to PDF
ros2 run tf2_ros tf2_echo world panda_hand   # print transform

A.2 Minimal ROS 2 Python Node

#!/usr/bin/env python3
import rclpy
from rclpy.node import Node
from std_msgs.msg import String


class MinimalNode(Node):
    def __init__(self):
        super().__init__('minimal_node')

        # Publisher
        self.pub = self.create_publisher(String, '/chatter', 10)

        # Subscriber
        self.create_subscription(String, '/chatter', self._cb, 10)

        # Timer (1 Hz)
        self.create_timer(1.0, self._timer_cb)
        self.get_logger().info('Minimal node started.')

    def _timer_cb(self) -> None:
        msg = String()
        msg.data = 'Hello from minimal_node'
        self.pub.publish(msg)

    def _cb(self, msg: String) -> None:
        self.get_logger().info(f'Received: {msg.data}')


def main():
    rclpy.init()
    rclpy.spin(MinimalNode())
    rclpy.shutdown()


if __name__ == '__main__':
    main()

A.4 MoveItPy Cheat Sheet

import moveit_py
from moveit.planning import MoveItPy, PlanRequestParameters
from geometry_msgs.msg import PoseStamped

# Initialise
moveit   = moveit_py.MoveItPy(node_name='my_node')
arm      = moveit.get_planning_component('panda_arm')
scene    = moveit.get_planning_scene_monitor()

# Set start state to current
arm.set_start_state_to_current_state()

# Set goal by pose
target = PoseStamped()
target.header.frame_id    = 'panda_link0'
target.pose.position.x    = 0.4
target.pose.orientation.x = 1.0   # pointing down
arm.set_goal_state(pose_stamped_msg=target, pose_link='panda_hand')

# Set goal by named state
arm.set_goal_state(configuration_name='ready')

# Set goal by joint values
arm.set_goal_state(joint_values={
    'panda_joint1': 0.0,
    'panda_joint2': -0.785,
    # ...
})

# Plan
params = PlanRequestParameters(moveit, 'panda_arm')
params.max_velocity_scaling_factor     = 0.3
params.max_acceleration_scaling_factor = 0.1
plan = arm.plan(single_plan_parameters=params)

# Execute
if plan:
    moveit.execute(plan.trajectory, controllers=[])

# Cartesian path
plan, fraction = arm.compute_cartesian_path(
    waypoints=[target],
    max_step=0.005,      # 5 mm interpolation
    jump_threshold=0.0,  # 0 = disable jump check
)
if fraction >= 0.95:
    moveit.execute(plan.trajectory, controllers=[])

Appendix B · Panda DH Parameter Table

The Denavit-Hartenberg parameters describe the kinematic chain from the base frame to the end-effector. All angles in radians, distances in metres. The convention follows Craig's modified DH (proximal) form as used in the Panda's URDF.

Table B.1 — Panda (FR3) modified DH parameters
Joint a (m) d (m) α (rad) θ offset (rad) Range min (rad) Range max (rad)
J100.33300−2.89732.8973
J200−π/20−1.76281.7628
J300.316π/20−2.89732.8973
J40.08250π/20−3.0718−0.0698
J5−0.08250.384−π/20−2.89732.8973
J600π/20−0.01753.7525
J70.0880.107π/20−2.89732.8973
Flange00.103400Fixed (no joint)

Notes on the table:

  • J4 has an asymmetric range (−3.07 to −0.07 rad) because the zero-torque configuration places J4 at approximately −π/4, not at 0. This is a DH convention artefact, not a mechanical limit.
  • J6 has an unusual positive range (up to 3.75 rad ≈ 215°) because wrist configurations that wrap around the flange are mechanically valid.
  • The Flange frame is the physical flange of the arm. The panda_hand frame is a fixed transform of +107 mm in Z from the flange. The TCP (tool centre point) panda_EE is a further fixed transform.

B.1 Reading the DH Table in Python

import numpy as np

# Modified DH parameters: [a, d, alpha, theta_offset]
PANDA_DH = np.array([
    [0.0,      0.333,   0.0,           0.0],
    [0.0,      0.0,    -np.pi / 2,     0.0],
    [0.0,      0.316,   np.pi / 2,     0.0],
    [0.0825,   0.0,     np.pi / 2,     0.0],
    [-0.0825,  0.384,  -np.pi / 2,     0.0],
    [0.0,      0.0,     np.pi / 2,     0.0],
    [0.088,    0.107,   np.pi / 2,     0.0],
])


def dh_transform(a: float, d: float, alpha: float, theta: float) -> np.ndarray:
    """Return the 4x4 homogeneous transform for one DH link."""
    ct, st = np.cos(theta), np.sin(theta)
    ca, sa = np.cos(alpha), np.sin(alpha)
    return np.array([
        [ct,  -st * ca,  st * sa,  a * ct],
        [st,   ct * ca, -ct * sa,  a * st],
        [0.0,  sa,       ca,       d     ],
        [0.0,  0.0,      0.0,      1.0   ],
    ])


def forward_kinematics(q: np.ndarray) -> np.ndarray:
    """Return 4x4 EEF transform given 7 joint angles (rad)."""
    T = np.eye(4)
    for i, (row, qi) in enumerate(zip(PANDA_DH, q)):
        a, d, alpha, offset = row
        T = T @ dh_transform(a, d, alpha, qi + offset)
    return T


if __name__ == '__main__':
    q_home = np.array([0.0, -np.pi/4, 0.0, -3*np.pi/4, 0.0, np.pi/2, np.pi/4])
    T = forward_kinematics(q_home)
    print('EEF position (home):', T[:3, 3].round(4))

Appendix C · Troubleshooting Guide

This section lists the most common problems encountered when following the tutorial, together with their causes and solutions.

C.1 Installation and Setup

Table C.1 — Installation issues
SymptomLikely causeFix
ros2: command not found ROS 2 setup script not sourced Add source /opt/ros/humble/setup.bash to ~/.bashrc
Package 'franka_ros2' not found franka_ros2 workspace not built or not sourced Run colcon build in the workspace, then source install/setup.bash
MathJax equations not rendering in browser No internet connection (CDN not reachable) Open HTML files via a local web server or connect to the internet
ImportError: No module named 'moveit_py' moveit_py package not built or Python path not set Source the MoveIt 2 workspace; ensure PYTHONPATH includes install/lib/python3.x/site-packages

C.2 Simulation

Table C.2 — Simulation issues
SymptomLikely causeFix
Gazebo opens but arm falls through floor Physics plugin not loading or gravity model incorrect Confirm use_fake_hardware:=true in the launch file; restart Gazebo
move_group fails to find IK solution TRAC-IK plugin not installed or goal pose is out of reach Install ros-humble-trac-ik-kinematics-plugin; verify goal is within 855 mm reach
Planning always fails with "No valid goal configurations" Goal pose is in self-collision Visualise in RViz; move goal slightly; check z > 0.1 (above table)
Controllers not loading after launch controller_manager not discovering YAML config Check that ros2 control list_controllers shows expected controllers; re-run spawner commands

C.3 Real Hardware

Table C.3 — Real hardware issues
SymptomLikely causeFix
Cannot ping robot (192.168.1.1) Wrong NIC, NIC not configured, cable unplugged Run ip addr to confirm NIC has 192.168.1.x address; check cable is plugged into the dedicated NIC, not the laptop port
Robot enters protective stop immediately FCI control packet jitter; NIC shared with other traffic Disable Wi-Fi, close bandwidth-heavy applications; confirm PREEMPT_RT kernel with uname -r
libfranka error: "Connection timeout" FCI not enabled on robot pendant On the robot web interface (http://192.168.1.1), unlock the robot and enable FCI mode

Gripper does not close Gripper action server not running or wrong topic name Run ros2 action list; confirm /fr3_gripper/grasp is present; start franka_gripper node if missing

C.4 MoveIt 2 Planning

Table C.4 — MoveIt 2 planning issues

C.5 Quick Diagnostic Commands

# Check all controllers are active
ros2 control list_controllers | grep -v unconfigured

# Watch joint states at 10 Hz
ros2 topic echo --once /joint_states

# Check planning scene for collision objects
ros2 topic echo --once /monitored_planning_scene | grep "object_colors"

# Confirm MoveIt 2 move_group is alive
ros2 service call /move_group/get_planner_params \
    moveit_msgs/srv/GetPlannerParams {}

# Check TF tree (look for broken chain)
ros2 run tf2_tools view_frames && evince frames.pdf

# Tail the robot error log
ros2 topic echo /franka_robot_state_broadcaster/robot_state \
    | grep -A2 "robot_mode\|error"

# Force error recovery after protective stop
ros2 service call /error_recovery franka_msgs/srv/ErrorRecovery
