Chapter 8

MoveIt 2 Deep Dive

Chapters 4 and 5 used MoveIt 2 as a black box: send a goal, get a trajectory. This chapter opens the box. You will learn how MoveIt 2's internal pipeline processes a goal — from scene representation and collision checking to planner selection, constraint handling, and trajectory post-processing. Understanding this pipeline lets you diagnose planning failures, tune planner parameters, enforce task-specific motion constraints, and integrate custom planners.

8.1 MoveIt 2 Architecture

MoveIt 2 is built around a central ROS 2 node called move_group. All planning requests — whether from Python, C++, or RViz — pass through this node. Figure 8.1 shows the major components and their relationships.

When you call arm.plan() in Python, the request travels as a ROS 2 action goal to move_group, which then:

  1. Locks the planning scene (robot model + world objects).
  2. Calls the configured planner plugin (default: OMPL).
  3. Post-processes the raw path (time parameterisation, smoothing).
  4. Returns the trajectory; execution is triggered by moveit.execute().

8.2 The Planning Scene

The planning scene is MoveIt 2's representation of the world. It contains the robot's current joint state, all collision objects (boxes, cylinders, meshes), attached objects (gripper payload), and the allowed collision matrix (ACM). The planner queries the scene to check whether candidate configurations are collision-free.

8.2.1 Adding Collision Objects in Python

from moveit.planning import MoveItPy
from moveit_msgs.msg import CollisionObject
from shape_msgs.msg import SolidPrimitive
from geometry_msgs.msg import Pose

def add_box(moveit: MoveItPy, name: str,
            x: float, y: float, z: float,
            sx: float, sy: float, sz: float) -> None:
    """Add a box collision object to the planning scene."""
    scene = moveit.get_planning_scene_monitor()

    obj = CollisionObject()
    obj.id             = name
    obj.header.frame_id = 'panda_link0'

    primitive      = SolidPrimitive()
    primitive.type = SolidPrimitive.BOX
    primitive.dimensions = [sx, sy, sz]

    pose = Pose()
    pose.position.x = x
    pose.position.y = y
    pose.position.z = z
    pose.orientation.w = 1.0

    obj.primitives        = [primitive]
    obj.primitive_poses   = [pose]
    obj.operation         = CollisionObject.ADD

    with scene.read_write() as s:
        s.apply_collision_object(obj)
        s.current_state.update()

# Example: add a 0.4 x 0.6 x 0.02 m table at z = 0.0
# add_box(moveit, 'table', 0.5, 0.0, 0.0, 0.4, 0.6, 0.02)

8.2.2 Attaching Objects to the Gripper

After grasping an object, you must tell MoveIt 2 that the object is now attached to the robot. The planner then treats it as part of the robot body for collision checking: 

from moveit_msgs.msg import AttachedCollisionObject

def attach_object(moveit: MoveItPy, obj_id: str, link: str = 'panda_hand') -> None:
    scene = moveit.get_planning_scene_monitor()
    aco = AttachedCollisionObject()
    aco.link_name    = link
    aco.object.id    = obj_id
    aco.object.operation = CollisionObject.ADD
    with scene.read_write() as s:
        s.attach_collision_object(aco)
        s.current_state.update()

8.3 Motion Planners

MoveIt 2 uses a plugin architecture for planners. The default plugin is OMPL (Open Motion Planning Library), which provides a suite of sampling-based planners [1].

Table 8.1 — Common OMPL planners and their characteristics
Planner Type Optimal? Best for
RRTConnect Bidirectional tree No Fast feasibility; default in MoveIt 2
RRT* Single tree, rewiring Asymptotically Shortest-path tasks with time budget
LBKPIECE Lazy bidirectional No Narrow passages, cluttered environments
PRM Roadmap Asymptotically Repeated queries in a fixed environment
STOMP Stochastic trajectory optimisation Local Smooth trajectories when start is near goal

8.3.1 Selecting a Planner in Python

# Set the planner before calling plan()
arm.set_planning_pipeline_id('ompl')
arm.set_planner_id('RRTConnectkConfigDefault')   # fastest

# Increase time budget for difficult scenes
arm.set_planning_time(10.0)   # seconds

# Attempt multiple planning runs and return the shortest
arm.set_num_planning_attempts(5)

8.4 Motion Constraints

Constraints restrict the set of valid configurations the planner may visit. MoveIt 2 supports four types, which can be combined:

Table 8.2 — MoveIt 2 constraint types
TypeWhat it restrictsExample use
JointConstraint Single joint must stay within [lower, upper] Keep elbow below shoulder height
PositionConstraint EEF position must stay inside a volume (box, sphere) Confine EEF above the table
OrientationConstraint EEF orientation must stay within an angular tolerance Keep a cup upright throughout the motion
VisibilityConstraint A target point must remain visible to an on-robot sensor Keep camera pointed at a marker

8.4.1 Upright Orientation Constraint

from moveit_msgs.msg import Constraints, OrientationConstraint
from geometry_msgs.msg import Quaternion

def make_upright_constraint(link: str = 'panda_hand',
                             tolerance_deg: float = 15.0) -> Constraints:
    """Keep the EEF within tolerance_deg of the upright orientation."""
    import math
    tol = math.radians(tolerance_deg)

    oc = OrientationConstraint()
    oc.link_name           = link
    oc.header.frame_id     = 'panda_link0'
    oc.orientation         = Quaternion(x=1.0, y=0.0, z=0.0, w=0.0)  # pointing down
    oc.absolute_x_axis_tolerance = tol
    oc.absolute_y_axis_tolerance = tol
    oc.absolute_z_axis_tolerance = tol
    oc.weight              = 1.0

    c = Constraints()
    c.name                 = 'upright'
    c.orientation_constraints = [oc]
    return c

8.5 Advanced Planning Techniques

8.5.1 Pipeline Plugins

MoveIt 2 supports a planning pipeline with optional pre- and post-processing plugins. The default pipeline runs OMPL then applies TOTG (Time-Optimal Trajectory Generation) for time parameterisation. You can replace individual stages: 

# In moveit_cpp.yaml
planning_pipelines:
  pipeline_names: [ompl, pilz]   # multiple pipelines, selectable at runtime

ompl:
  planning_plugins: [ompl_interface/OMPLPlanner]
  request_adapters:
    - default_planning_request_adapters/ResolveConstraintFrames
    - default_planning_request_adapters/ValidateWorkspaceBounds
    - default_planning_request_adapters/CheckStartStateBounds
  response_adapters:
    - default_planning_response_adapters/AddTimeOptimalParameterization
    - default_planning_response_adapters/ValidateSolution

8.5.2 Pilz Industrial Motion Planner

The Pilz planner generates deterministic, repeatable paths without random sampling — ideal for production environments where the same motion must be executed identically every run. It supports three motion types:

  • PTP (Point-to-Point) — joint-interpolated move, fastest.
  • LIN (Linear) — Cartesian straight-line move.
  • CIRC (Circular) — arc through an intermediate waypoint.
# Use the Pilz LIN planner for a Cartesian straight-line move
arm.set_planning_pipeline_id('pilz')
arm.set_planner_id('LIN')

8.5.3 Trajectory Caching

For repetitive tasks the same plan is computed many times. MoveIt 2's trajectory cache plugin stores successful plans keyed by start-and-goal hash. On repeated identical requests the plan is returned instantly from cache, skipping the planner entirely.

8.6 Code Examples

8.6.1 Full Planning Pipeline with Constraints and Collision Objects

#!/usr/bin/env python3
"""
moveit_deep_dive.py — demonstrates scene management, constraints,
and planner selection in a single planning request.
"""
import rclpy
from rclpy.node import Node
from geometry_msgs.msg import PoseStamped, Quaternion
from moveit_msgs.msg import (CollisionObject, Constraints,
                              OrientationConstraint)
from shape_msgs.msg import SolidPrimitive
import moveit_py
from moveit.planning import MoveItPy


class DeepDiveNode(Node):
    def __init__(self):
        super().__init__('moveit_deep_dive')
        self.moveit: MoveItPy = moveit_py.MoveItPy(
            node_name='moveit_deep_dive')
        self.arm   = self.moveit.get_planning_component('panda_arm')
        self.scene = self.moveit.get_planning_scene_monitor()

    # ── Scene management ──────────────────────────────────────────────
    def add_table(self) -> None:
        obj = CollisionObject()
        obj.id              = 'table'
        obj.header.frame_id = 'panda_link0'

        prim = SolidPrimitive()
        prim.type            = SolidPrimitive.BOX
        prim.dimensions      = [0.8, 1.2, 0.02]  # 80 x 120 x 2 cm

        from geometry_msgs.msg import Pose
        pose             = Pose()
        pose.position.x  = 0.5
        pose.position.z  = -0.01   # just below z=0
        pose.orientation.w = 1.0

        obj.primitives      = [prim]
        obj.primitive_poses = [pose]
        obj.operation       = CollisionObject.ADD

        with self.scene.read_write() as s:
            s.apply_collision_object(obj)
            s.current_state.update()
        self.get_logger().info('Table added to planning scene.')

    # ── Upright constraint ────────────────────────────────────────────
    @staticmethod
    def upright_constraint(tol_deg: float = 15.0) -> Constraints:
        import math
        tol = math.radians(tol_deg)
        oc  = OrientationConstraint()
        oc.link_name                  = 'panda_hand'
        oc.header.frame_id            = 'panda_link0'
        oc.orientation                = Quaternion(x=1.0, y=0.0, z=0.0, w=0.0)
        oc.absolute_x_axis_tolerance  = tol
        oc.absolute_y_axis_tolerance  = tol
        oc.absolute_z_axis_tolerance  = tol
        oc.weight                     = 1.0
        c       = Constraints()
        c.name  = 'upright'
        c.orientation_constraints = [oc]
        return c

    # ── Plan with custom settings ─────────────────────────────────────
    def plan_to_pose(self, x: float, y: float, z: float) -> bool:
        self.arm.set_start_state_to_current_state()

        target = PoseStamped()
        target.header.frame_id     = 'panda_link0'
        target.pose.position.x     = x
        target.pose.position.y     = y
        target.pose.position.z     = z
        target.pose.orientation    = Quaternion(x=1.0, y=0.0, z=0.0, w=0.0)
        self.arm.set_goal_state(
            pose_stamped_msg=target, pose_link='panda_hand')

        # Planner selection
        self.arm.set_planning_pipeline_id('ompl')
        self.arm.set_planner_id('RRTConnectkConfigDefault')
        self.arm.set_planning_time(5.0)
        self.arm.set_num_planning_attempts(3)

        from moveit.planning import PlanRequestParameters
        params = PlanRequestParameters(self.moveit, 'panda_arm')
        params.planning_pipeline_id  = 'ompl'
        params.planner_id            = 'RRTConnectkConfigDefault'
        params.planning_time         = 5.0
        params.max_velocity_scaling_factor      = 0.3
        params.max_acceleration_scaling_factor  = 0.1

        plan = self.arm.plan(single_plan_parameters=params)
        if not plan:
            self.get_logger().error('Planning failed.')
            return False

        result = self.moveit.execute(plan.trajectory, controllers=[])
        return bool(result)


def main():
    rclpy.init()
    node = DeepDiveNode()
    rclpy.spin_once(node, timeout_sec=1.0)

    node.add_table()
    success = node.plan_to_pose(x=0.4, y=0.1, z=0.4)
    node.get_logger().info(f'Motion {"succeeded" if success else "failed"}.')

    node.destroy_node()
    rclpy.shutdown()


if __name__ == '__main__':
    main()

Exercises

  1. Add a second collision box to the planning scene that blocks the direct path between the start and goal. Observe the planner tree in RViz; does the path detour around the obstacle?
  2. Switch to the Pilz LIN planner and compare the resulting trajectory to RRTConnect. Which produces a straighter Cartesian path? Measure the maximum deviation from the straight-line in each case.
  3. Apply the upright orientation constraint and attempt a motion that would normally require tipping the end-effector. How does the constraint change the path length? Does the planner fail more often?
  4. Increase set_planning_time from 5 to 30 seconds while using RRT*. Observe how the trajectory cost (total joint displacement) decreases as the planner is given more time to optimise.

Key Terms

move_group
The central MoveIt 2 ROS 2 node that receives planning requests, manages the planning scene, and coordinates planner plugins.
Planning scene
MoveIt 2's representation of the world: robot model, joint state, collision objects, attached objects, and the allowed collision matrix.
Collision object
A geometric primitive (box, cylinder, mesh) added to the planning scene so the planner avoids it.
OMPL
Open Motion Planning Library — a collection of sampling-based planners (RRT, PRM, LBKPIECE) used as the default plugin in MoveIt 2.
RRTConnect
A bidirectional RRT variant that grows two trees (from start and goal) and attempts to connect them; the default planner in MoveIt 2.
Time-Optimal Trajectory Generation (TOTG)
A post-processing step that assigns time stamps to a collision-free path to maximise execution speed within joint velocity and acceleration limits.
OrientationConstraint
A MoveIt 2 constraint that requires the end-effector orientation to remain within a specified angular tolerance of a reference orientation.
Pilz planner
A deterministic MoveIt 2 planner that generates repeatable PTP, LIN, and CIRC motions without random sampling.
Allowed collision matrix (ACM)
A table that specifies which pairs of robot links may touch without being treated as a collision (e.g., adjacent links).
